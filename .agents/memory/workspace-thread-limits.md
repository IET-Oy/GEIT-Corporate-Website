---
name: Workspace thread limits
description: Handling Vite or Rust-backed tool crashes when the workspace approaches its process/task cap.
---

A Vite development workflow can fail with `failed to spawn thread: Resource temporarily unavailable` when the workspace cgroup's process/task usage is near its limit. Serialized platform test and production-build invocations can also disconnect the CodeExecution worker before returning results. Inspect `pids.events` and `memory.events` separately: a rising PID `max` counter confirms task-limit events, while cumulative `oom_kill` counters do not prove that the latest command was OOM-killed. Neither event alone establishes a code syntax, test, or build failure. Check current and maximum task and memory counts, avoid parallel tests/builds, and do not kill unrelated processes. A large, sleeping `MainThread` chain may belong to a live shell-execution scope rather than an orphaned test; do not terminate it without reliable ownership or its managed task handle. Repeated diagnostic shell calls can coincide with growing worker counts, so stop probing when resource pressure remains critical. A working shell probe does not prove that the CodeExecution or test runner is healthy.

**Why:** In this workspace, the PID `max` counter increased around a test timeout, while the OOM counters stayed unchanged during that test. A later process inspection found many sleeping Node workers under live parent chains and no safely attributable test process; terminating by PID could have disrupted Replit's execution runtime.

**How to apply:** When a Vite or Rust-backed workflow reports thread-spawn errors, first inspect process/task and memory headroom plus cgroup event counters. If a test times out without output, report it as inconclusive and stop rather than repeating it. If a workspace restart leaves the same pressure and processes cannot be safely attributed, use Replit's runtime-level recovery path instead of repeated resets or manual PID kills. Retry checks only after resources recover, preferably in small individual commands; report them as incomplete until they actually finish.
